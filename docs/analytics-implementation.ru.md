# Аналитика внешнего UI

Маршрут: `#gelios/analytics`, пункт «Аналитика» в пространстве Studio Gelios.
Код интерфейса: `ui/src/studio-analytics.js`, расчёты: `studio-analytics-domain.js`.
В этой реализации изменены только внешний UI/API. CRM-приложение и его схема
не изменялись; запросы к живой CRM и деплой не выполнялись.

## Данные и расчёты

API отдаёт полные списки по курсору через `/api/v1/studio/records/{resource}`.
Используются `clients`, `products`, `packages`, `bookings`, `sessions`,
`transactions`, `payments`, `expenses`. Ключ CRM остаётся на сервере.
Ошибка отдельного источника делает зависимые показатели недоступными,
а не равными нулю. Общий баннер указывает на неполную загрузку.

Деньги рассчитываются через `BigInt` и передаются строками целых копеек;
микрорубли CRM конвертируются только без потери копеек. Часовой пояс — Москва.
Текущий месяц сравнивается с теми же днями прошлого месяца, прошедший —
с полным предыдущим. Начисленные месячные расходы учитываются целиком:
пропорционального распределения аренды по дням нет.

Доступны поступления, начисленные расходы и выплаты, категории и типы затрат,
занятия, посещения, загрузка групп, отмены, неявки и клиентские когорты.
«Вернулись» означает посещение после пропуска предыдущего полного месяца;
продолжающие ходить выделены отдельно. «Без посещений» сравнивает текущий
и предыдущий сопоставимый период. Когорты опираются на доступную историю CRM.

Без дополнительных контрактов CRM намеренно недоступны:

- Доход по проведённым занятиям, прибыль и рентабельность: нет неизменяемой
  денежной стоимости каждого списания.
- Денежные предоплаты и долги на конец исторического месяца: текущие остатки
  пакетов не заменяют исторические денежные обязательства.
- Возвраты по месяцам при наличии накопленных возвратов без отдельных дат.
  В этом случае денежный поток тоже недоступен.

В интерфейсе для этих показателей показываются прочерк и причина. Отдельный
CRM-агент может предоставить новые контракты; тогда следует расширить domain
и тесты, сохранив различие поступлений и заработанного дохода.

## Расходы

Контракты внешнего API описаны в `studio-api.md`. Форма поддерживает создание,
исправление, неоплаченный расход и удаление с подтверждением. Назначение
месяца начисления и даты выплаты объясняется рядом с полями.

Сохранение блокирует повторное нажатие и переход по навигации. При неизвестном
результате запрос автоматически не повторяется; значения сохраняются в форме,
повторная отправка блокируется до закрытия формы и проверки журнала.
Существующий CRM save не даёт идемпотентности создания. Удаление также требует
проверки журнала после неопределённого ответа. Живую совместимость контрактов
нужно проверять после согласования версии с CRM-агентом.

## Проверки

- `cd ui && npm run check && npm test`: 46 тестов проходят.
- `npm run test:browser:analytics`: локальный браузерный сценарий с
  синтетическими ответами; 7 вкладок, пагинация, создание/правка/удаление,
  копейки, неоплаченный расход, валидация, ожидающий и неизвестный результат,
  частичная загрузка, будущий месяц, переход к клиенту и мобильные размеры.
- `npm run test:browser:design`: существующие экраны Gelios и тема Terfit.
- Python: 244 passed, 43 skipped; один существующий сбой
  `test_compose_api_is_independent_and_has_no_telegram_token` ожидает литерал
  `8000:8000`, тогда как Compose уже использует `${API_HOST_PORT:-8000}:8000`.

Браузерные сценарии требуют доступного Playwright и локального сервера UI.
`PLAYWRIGHT_MODULE`, `UI_SMOKE_CHROME`, `UI_SMOKE_URL` и
`UI_SMOKE_ARTIFACT_DIR` задают имеющиеся runtime, браузер, сервер и каталог
скриншотов. Это проверки на тестовых ответах, не подтверждение stage-релиза.
