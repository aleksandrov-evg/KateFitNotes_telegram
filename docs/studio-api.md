# Gelios: серверное подключение Twenty по API-ключу

OAuth не используется. UI обращается к FastAPI после обычного входа в KateFitNotes; FastAPI обращается к Twenty с серверным API-ключом. Существующие маршруты Terfit сохраняются. По умолчанию интеграция выключена.

## Настройка staging

1. Сначала выпустить изменённую команду studio-record-past-attendance в Twenty: она больше не требует userWorkspaceId, но её HTTP route сохраняет isAuthRequired=true. Старый выпуск с API-ключом вернёт ACTOR_REQUIRED.
2. В секретах сервиса KateFitNotes API установить CRM_ENABLED=1, CRM_BASE_URL=http://crm-stage.lan и CRM_API_KEY=<ключ staging workspace>. Для внешнего домена использовать HTTPS. Ключ должен иметь необходимые права на студийные объекты/команды. Существующий подходящий ключ можно использовать; отдельный ключ интеграции удобнее для отзыва и ограничения прав.
3. Перезапустить сервис API. Не включать CRM_API_KEY в Vite/public env, фронтенд, Git, логи или запросы браузера. API-key клиента и автора браузер передавать не может.
4. Войти в KateFitNotes. GET /api/v1/studio/auth/status вернёт configured:true, auth_mode:api_key. Это только проверка наличия конфигурации, не проверки удалённых прав/доступности.
5. Проверить POST /api/v1/studio/attendance/preview на тестовом клиенте/пакете. Preview не создаёт записей и не списывает посещение.
6. Затем проверить запись и повтор с тем же ключом на выделенных fixtures. Реальные CRM-записи в локальных тестах не создаются.

Настройка не требует callback, consent, refresh token или отдельного OAuth клиента. API-ключ действует после перезапуска и в нескольких workers; отдельное хранилище пользовательских подключений не требуется.

## Маршруты

Все маршруты требуют JWT KateFitNotes.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | /api/v1/studio/auth/status | Наличие конфигурации без раскрытия ключа |
| GET | /api/v1/studio/records/{resource} | Страница клиентов/продуктов/пакетов/посещений/занятий/журнала |
| POST | /api/v1/studio/clients | Создать контакт с устойчивым clientId |
| POST | /api/v1/studio/package-payments/confirm | Подтвердить полученную оплату и создать пакет доменной командой |
| POST | /api/v1/studio/bookings/create | Добавить обычного участника, RESERVE и событие |
| POST | /api/v1/studio/bookings/cancel | Отмена студией, RELEASE и событие |
| POST | /api/v1/studio/sessions/create | Создать будущее/прошедшее занятие и обязательное событие, без списаний |
| POST | /api/v1/studio/attendance/preview | Сервер принудительно задаёт previewOnly=true |
| POST | /api/v1/studio/attendance/record-past | Внести завершённое занятие через доменную команду CRM |

Пример тела preview/record-past:

```json
{
  "personId": "<UUID клиента>",
  "membershipId": "<UUID пакета>",
  "startsAt": "2026-10-13T18:30:00+03:00",
  "endsAt": "2026-10-13T19:25:00+03:00",
  "reason": "По журналу посещений",
  "source": "ATTENDANCE_LOG",
  "idempotencyKey": "<стабильный ключ операции>"
}
```

Дополнительные поля: existingClassSessionId, sourceDetails. Для OTHER пояснение проверяет CRM. Время включает часовой пояс. recordedBy, actorId, apiKey и previewOnly в запросе браузера запрещены.

Форма позволяет выбрать существующее завершённое занятие с совпадающими временем, форматом и длительностью; иначе команда создаёт историческое занятие.

При API-ключе recordedBy остаётся пустым. Время внесения, причина, источник и журнал списаний сохраняются. При пользовательском контексте Twenty автор по-прежнему берётся из этого контекста.

Клиент сохраняет один idempotencyKey для preview, подтверждения и повторов. При timeout мутации автоматического повтора нет: 502 требует проверить историю и использовать прежний ключ. Отказ ключа/его прав возвращается как ошибка серверного подключения (502), а не как истечение входа пользователя KateFitNotes. Доменные конфликты CRM сохраняют код и 4xx.

## Что ещё не сделано

- Изменения локальные, staging и production не обновлялись.
- Основной UI подключён: переключатель Terfit/Gelios, обзор, список и карточка клиента, создание контакта, оплата пакета, preview/внесение прошедшей тренировки, посещения и журнал. Календарь включает временную сетку, создание слотов и управление обычными участниками. Редактирование контактов, проведение обычных бронирований, PAYG, сплиты и лиды пока выполняются в CRM.
- Общая транзакция/блокировка между CRM-мутациями остаётся отдельным условием готовности к конкурентным операциям.
- Проверка удалённых прав и положительный preview на staging нужны после выпуска.

Локальная проверка без БД и живой CRM:

```bash
uv run --locked pytest tests/test_studio_api.py tests/test_studio_records.py tests/test_studio_calendar_api.py tests/test_api.py tests/test_settings.py -q
npm --prefix ui run check
npm --prefix ui test
```

## Работа интерфейса

Переключатель находится в боковом меню над навигацией; на телефоне сначала открыть меню. Режимы имеют отдельные данные и маршруты: Terfit сохраняет прежние страницы, Gelios использует #gelios/overview и серверные /studio/*.

Списки CRM загружаются страницами по курсору; разрешены только resources clients, products, packages, bookings, sessions, transactions, events. Максимум UI — 100 страниц по 100 записей на список; далее требуется серверная фильтрация. API-ключ в UI не присутствует.

Создание клиента принимает clientId (UUID), firstName, lastName, phone, email. Телефон нормализуется в российский национальный номер. Повтор с тем же UUID и теми же контактами возвращает уже созданного клиента; при изменённых данных — 409. Проверка существующего телефона предотвращает последовательные дубли, но не заменяет уникальный индекс при конкурентном создании в разных вкладках.

Оплата принимает personId, productId, paidAt с часовым поясом, amount, paymentMethod CASH/SBP/CARD, idempotencyKey; необязательные externalId/fiscalReceiptId. UI берёт цену/количество посещений из продукта, CRM повторно проверяет их. Прямого POST пакета или изменения баланса UI не делает.

UI сохраняет отправленное тело и ключ незавершённой операции в sessionStorage этой вкладки. Перезагрузка и повторный вход в той же вкладке сохраняют возможность безопасного повтора. При неопределённом ответе/доменном конфликте форма блокируется: сначала проверить списки и журнал, затем повторить прежнее тело либо явно сбросить после ручной проверки CRM. Сброс ничего не отменяет на сервере. При закрытии вкладки ключ может потеряться — перед новой оплатой обязательно сверить CRM. Не использовать несколько вкладок для одной финансовой операции.

## Браузерная проверка

В режиме Gelios выпадающие списки используют общий компонент ui/src/studio-select.js вместо системного popup. Выбор клиента в оплате, внесении посещения и календарных диалогах фильтруется по каждому символу подстроки имени/телефона/email без учёта регистра. Ввод текста сбрасывает прежний UUID, выбор подтверждается только вариантом из списка. Календарь сохраняет исходные ограничения доступности клиентов/пакетов. Есть стрелки, Enter, Escape, Tab, закрытие вне меню и состояние «Ничего не найдено»; отключённые/незавершённые формы остаются отключёнными. Исходный select хранит значение для FormData и существующих обработчиков, но системное меню не открывается. Terfit остаётся без изменений. Проверки — test:browser:design и test:browser:sessions; для выпуска достаточно обновить UI.

ui/scripts/smoke_studio.mjs проверяет переключение, создание контакта, оплату, preview, потерю ответа после списания, повтор после перезагрузки, журнал, мобильную ширину и выключенную CRM. Все /api/v1/* перехватываются моками; реальные записи не создаются. Нужен доступный Playwright и его браузер либо UI_SMOKE_CHROME с путём к установленному Chrome; зависимость сайта не менялась.

Запустить UI на отдельном локальном порту:

```bash
UI_PORT=5184 python3 ui/scripts/dev_server.py
```

В другом терминале (если Playwright установлен рядом с UI):

```bash
npm --prefix ui run test:browser
```

PLAYWRIGHT_MODULE может указывать абсолютный путь к имеющемуся playwright/index.mjs. UI_SMOKE_URL меняет адрес локального UI; UI_SMOKE_ARTIFACT_DIR — существующий каталог для скриншотов (по умолчанию системный временный каталог).

Регрессия HTTP/IP-адреса: npm --prefix ui run test:browser:http. Тест открывает полностью перехваченный HTTP-origin (без локального сервера), где crypto.randomUUID отсутствует. Проверяет открытие подтверждения и единственный запрос оплаты с UUID v4; реальные оплаты не создаются. Генератор использует crypto.getRandomValues, без Math.random. Для внешнего размещения всё равно нужен HTTPS: JWT/контакты не следует передавать по незащищённой сети.

## Выпуск

Бизнес-аудит UI: создание клиента требует события CLIENT_CREATED в studioEvents; отдельное прошедшее посещение теперь требует BOOKING_CREATED так же, как календарное. Ошибки всех шести изменяющих маршрутов дополнительно журналируются API с источником KATEFIT_UI и логином из JWT. При недоступном журнале возвращается AUDIT_UNCONFIRMED, успех не имитируется. Повтор с прежним ключом восстанавливает пропущенное успешное событие без повторного клиента/посещения; новая API-запись ошибки не создаётся. Preview, чтение, локальная валидация и FastAPI 422 до маршрута не входят в бизнес-аудит.

Сначала применить новую опцию CLIENT_CREATED в CRM и обновлённые функции, затем пересобрать API. Действующий серверный API-ключ должен иметь REST-права чтения/создания studioEvents. Исторические пропуски не восстанавливаются автоматически. Проверка аудита на моках: uv run pytest tests/test_studio_api.py tests/test_studio_records.py tests/test_studio_calendar_api.py tests/test_studio_audit.py -q. Полное описание границ и порядка выпуска — docs/gelios-ui-audit-coverage.ru.md в репозитории crm-twenty.

Оформление Gelios сохраняет компоновку последних макетов V2 из pencil.pen с фирменной палитрой: боковая панель 232 px, фон #FCF7F8, навигация #3B242B, основной акцент #B85160, мягкие блоки #FDF0F2, отступ рабочей области 40×48 px. Тема изолирована в ui/src/studio-theme.css через studio-mode/studio-shell и не меняет оформление Terfit. Оплата представлена формой и живым итогом справа; список пакетов расположен ниже. Клиенты, посещения, списания, календарь и диалоги используют те же размеры полей, кнопок и таблиц. Это визуальное обновление реализованных сценариев, а не добавление всех функций из макетов 00–25.

Проверка оформления: npm --prefix ui run test:browser:design. На моках проверяет все семь экранов при ширине 1440/1024/768/390 px, отсутствие горизонтального переполнения страницы, итог оплаты, диалог создания тренировки и сохранение темы Terfit. Скриншоты gelios-v2-* сохраняются в UI_SMOKE_ARTIFACT_DIR. Для этого обновления достаточно пересобрать UI; API/CRM-контракты и секреты не меняются.

Название в календарной форме заполняется автоматически русским названием формата (как fallback getSessionFormatLabel в CRM) и не редактируется вручную. При смене формата обновляется. CRM-команда также подставляет каноническое название при отсутствии name; старые сохранённые запросы с явным названием не переписываются.

Календарь позволяет создавать тренировки через сетку 07:00–23:00 (30 минут) либо кнопку «Новая тренировка». Форма задаёт название, формат, дату/время по Москве, длительность и места. Для прошлой даты обязательное подтверждение факта проведения; будущее — PLANNED, текущее — CONFIRMED, прошедшее — COMPLETED. Само создание ничего не списывает.

Команда sessions/create требует name, sessionFormat, startsAt, durationMinutes, capacity, status, pastConfirmed и idempotencyKey. Сначала выпустить новую studio-create-class-session в CRM, затем обновить API/UI. Повтор после потерянного ответа использует сохранённое тело/ключ; новая версия не требует новых секретов.

В форме также выбираются участники с подходящими пакетами. sessions/create принимает participants:[{personId,membershipId}] и attendanceReason для прошедшего занятия с людьми. Будущее резервирует посещения; прошедшее после серверного preview списывает фактические посещения. PERSONAL_EQUIPMENT — один клиент с PERSONAL пакетом; остальные обычные групповые форматы — GROUP_PACKAGE. Без участников создание ничего не списывает.

При выпуске применить новое nullable поле classSessions.creationRequest и изменённую функцию вместе. Поле хранит исходный список, обеспечивая повтор после частичного сбоя без подмены участников. Ошибка может означать уже созданный слот/часть людей: проверять карточку и повторять прежний запрос, не создавать новое занятие новым ключом.

Браузерная проверка сетки/создания: npm --prefix ui run test:browser:sessions, параметры Playwright/локального UI как выше.

После проверки CRM приложения на staging пересобрать отдельно KateFitNotes API (docker-compose.api.yml) и UI (docker-compose.ui.yml), сохранив действующие секреты/SQL-настройки. В Dokploy это Deploy соответствующих сервисов после сохранения Environment. Одного twenty apply недостаточно: он не обновляет контейнеры KateFitNotes.
