# Gelios: серверное подключение Twenty по API-ключу

OAuth не используется. UI обращается к FastAPI после обычного входа в KateFitNotes; FastAPI обращается к Twenty с серверным API-ключом. Существующие маршруты Terfit сохраняются. По умолчанию интеграция выключена.

## Настройка staging

1. Сначала выпустить изменённую команду studio-record-past-attendance в Twenty: она больше не требует userWorkspaceId, но её HTTP route сохраняет isAuthRequired=true. Старый выпуск с API-ключом вернёт ACTOR_REQUIRED.
2. В секретах сервиса KateFitNotes API установить CRM_ENABLED=1, CRM_BASE_URL=http://crm-stage.lan и CRM_API_KEY=<ключ staging workspace>. Для внешнего домена использовать HTTPS. Ключ должен иметь необходимые права на студийные объекты/команды. Существующий подходящий ключ можно использовать; отдельный ключ интеграции удобнее для отзыва и ограничения прав.
3. Перезапустить сервис API. Не включать CRM_API_KEY в Vite/public env, фронтенд, Git, логи или запросы браузера. API-key клиента и автора браузер передавать не может.
4. Войти в KateFitNotes. GET /api/v1/studio/auth/status вернёт configured:true, auth_mode:api_key. Это только проверка наличия конфигурации, не проверки удалённых прав/доступности.
5. Проверить POST /api/v1/studio/attendance/preview на тестовом клиенте/пакете. Preview не создаёт записей и не списывает посещение.
6. Затем проверить запись и повтор с тем же ключом на выделенных fixtures. Реальные CRM-записи в локальных тестах не создаются.

Настройка не требует callback, consent, refresh token или отдельного OAuth клиента. API-ключ действует после перезапуска и в нескольких workers; отдельное хранилище пользовательских подключений не требуется.

## Маршруты

Все маршруты требуют JWT KateFitNotes.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | /api/v1/studio/auth/status | Наличие конфигурации без раскрытия ключа |
| POST | /api/v1/studio/attendance/preview | Сервер принудительно задаёт previewOnly=true |
| POST | /api/v1/studio/attendance/record-past | Внести завершённое занятие через доменную команду CRM |

Пример тела preview/record-past:

```json
{
  "personId": "<UUID клиента>",
  "membershipId": "<UUID пакета>",
  "startsAt": "2026-10-13T18:30:00+03:00",
  "endsAt": "2026-10-13T19:25:00+03:00",
  "reason": "По журналу посещений",
  "source": "ATTENDANCE_LOG",
  "idempotencyKey": "<стабильный ключ операции>"
}
```

Дополнительные поля: existingClassSessionId, sourceDetails. Для OTHER пояснение проверяет CRM. Время включает часовой пояс. recordedBy, actorId, apiKey и previewOnly в запросе браузера запрещены.

При API-ключе recordedBy остаётся пустым. Время внесения, причина, источник и журнал списаний сохраняются. При пользовательском контексте Twenty автор по-прежнему берётся из этого контекста.

Клиент сохраняет один idempotencyKey для preview, подтверждения и повторов. При timeout мутации автоматического повтора нет: 502 требует проверить историю и использовать прежний ключ. Отказ ключа/его прав возвращается как ошибка серверного подключения (502), а не как истечение входа пользователя KateFitNotes. Доменные конфликты CRM сохраняют код и 4xx.
