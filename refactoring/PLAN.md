Рабочий план по [REVIEW.md](../REVIEW.md). Цель: вынести бизнес-логику из Telegram-хендлеров, покрыть её автотестами и подготовить общий бэкенд для будущего сайта.

**Правило среза:** этап закрыт только когда зелёные автотесты **и** ревьювер дал `MERGE`. Следующий этап не начинать без этого.

## Роли субагентов

На **каждом** этапе запускаются три субагента. Они не подменяют друг друга.

| Роль | Когда | Что делает | Чего не делает |
|------|-------|------------|----------------|
| **Разработчик** | первым | Реализует задачи этапа, правит прод-баги из списка этапа, логирует исключения | Не пишет полный набор автотестов этапа; не коммитит секреты; не меняет смысл `client` = телефон до этапа 11 |
| **Тестировщик** | после разработчика (или параллельно по контракту этапа) | Пишет автотесты как **обязательный результат этапа**; прогоняет их; фиксирует красные/зелёные | Не «чинит прод», чтобы подогнать тест, без явного бага; не ходит в прод-БД |
| **Код-ревьювер** | после кода и тестов | Читает diff этапа, проверяет покрытие критерия готовности, пишет саммари и вердикт `MERGE` / `NO MERGE` | Не пишет фичи и тесты; не мержит сам |

Порядок внутри этапа:

```
Разработчик  →  Тестировщик  →  Код-ревьювер  →  Результат проверки
     │                │                 │
  код этапа      автотесты        саммари + MERGE/NO MERGE
```

Если ревьювер ставит `NO MERGE`, этап возвращается разработчику. Тестировщик дополняет тесты, если ревью указало дыры в покрытии. Цикл повторяется, пока не будет `MERGE`.

## Общие правила (все этапы)

- Ответы и коммиты — на русском, без упоминания Cursor.
- Не коммитить `config.ini`, `.env`, `pg_db/`, `.idea/`, токены.
- Новые SQL-запросы — с `%s` / параметрами, соединения закрывать.
- Голый `except:` не добавлять; логировать `logging.exception`.
- Не менять формат `client_list` `{1,2,3}` и смысл `client` = телефон до этапа 11.
- Не внедрять FSM-фреймворк и не писать сайт, пока нет API (этап 12).
- `test.py` не образец: тесты живут в `tests/`.
- Бот однопользовательский до этапа 9; с этапа 9 состояние ключуется `chat_id`.
- Прод-данные не использовать в тестах. Отдельный `DATABASE_URL` / `pg_db_test:5433`.

## Как вести работу в Cursor

1. Открыть этот файл, выбрать **один** незакрытый этап сверху вниз.
2. Запустить субагента **разработчик** с промптом этапа.
3. Запустить субагента **тестировщик** — результат этапа = автотесты.
4. Запустить субагента **код-ревьювер** — получить саммари и `MERGE` / `NO MERGE`.
5. Заполнить **Результат проверки** (отдельные чекбоксы). Без них этап не закрыт.
6. Обновить строку в таблице «Статус этапов».
7. Коммит — только по просьбе пользователя, сообщение на русском.

Отчёты по закрытым этапам можно складывать в `refactoring/reports/stage-N.md` по шаблону выше.
